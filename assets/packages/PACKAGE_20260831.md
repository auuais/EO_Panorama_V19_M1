# Map package — 2026-08-31 14:00

Recalibration only: the previous maps were built with wrong HFOV/VFOV and a
wrong scale factor. Geometry is unchanged, so no RTL parameter moves.

Source: `assets/Maps_20260831_1400/`.

## The source folder mixes two generator runs

27 files dated 2026-08-31, 10 dated 2026-08-27 — the hazard
`eo_20260806/PACKAGE.md` was written about ("anything left in place is a
mixture of runs by construction"). Selecting blindly would have used stale
inputs, so what was taken is recorded here.

| installed as | taken from | shape | run |
|---|---|---|---|
| `eo_base_x/y_q16.bin` | `eo_base_x/y_q16.bin` | 655 x 480 | 08-31 |
| `ir_base_x/y_q16.bin` | **`ir_ppt_cam0_base_x/y_q16.bin`** | 621 x 480 | 08-31 |

**`ir_base_x/y_q16.bin` in the source folder was NOT used.** It is a 2026-08-27
leftover at 627 x 480 — a different geometry from the 621 x 480 the RTL uses.
The generator reads exactly that filename, so it would have been picked up
silently.

The 08-31 IR output is per-camera (`ir_ppt_cam0..5`), but **all six are
byte-identical**, so the naming carries no per-camera content and cam0 is the
map.

## Generation

Flags read out of the RTL, not guessed:

```
eo: --width 655 --height 480 --qy-clamp 1078 --record-bits 144 --drun-frac-bits 5
ir: --width 621 --height 480 --qy-clamp 510  --record-bits 96  --drun-frac-bits 4
```

* `qy-clamp` is `source_h - 2` (EO 1080, IR 512), per the generator's help.
* `record-bits` matches the installed `.mem` line widths, which the ROM
  decoders assume.
* `drun-frac-bits` is fixed by the RTL's Q-format shift, and the two differ:
  `EO_V19_DRUN_TO_Q16 = 11` gives 5, while `IrV19StreamingRenderer` hardcodes
  `<<< 12` ("dax/day are Q12.4") which gives 4.
* `--ir-cam23-fold-gate` was **not** used, matching the installed tables
  (min_row 25 with the gate off, 23 with it on). See the open item below.

Result: EO 31,680 records / 480 row entries, IR 28,800 / 480, record widths
144 and 96 bits. All match the RTL.

## Two things this package does NOT do

**It does not fix the four black EO edge rows.** Max row-window span is still
61 where the gate needs <= 60, on the same four rows. Confirmed against the
regenerated tables. That is RTL work, not a map change.

**Seam widths were left alone.** The 08-31 IR alpha LUTs are 30/15 entries
where the installed tables and `IR_V19_ALPHA_Y_LEN` / `_C_LEN` are 29/14, and
`IrV19StreamingRenderer` has "seams 29 px" in its geometry comment. Adopting
them is a coupled RTL change, and the EO alpha LUTs in the source folder are
from the stale 08-27 run and undocumented in the manifest. Left for a decision.

## Open item

The installed IR tables were generated without `--ir-cam23-fold-gate`, yet the
renderer does extend the fold-crossing cam2/cam3 seam (`cam23_fold_alpha_pos`).
If that extension reads source rows the row tables do not cover, the window
gate is optimistic there. Not changed here, to keep this package a pure
recalibration.
